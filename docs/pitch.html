An agent firewall.

The model is smarter. The code is faster. We sit in front of the tool and decide before anything runs.

01 — Problem

How do we know the agent left its sandbox?

  • A list of rules will be routed around. The agent is smarter than the author of the list.
  • A self-improving agent can mint tools. The action space is not closed.
  • A log after the write is already late.
  • The only move left: predict, and be faster.

02 — Axioms

What we assume. We do not relax these.

  1. A1The agent is smarter than we are.
  2. A2A cluster of deterministic checks is faster and lighter than the agent.
  3. A3The action space is open: it can create tools we never listed.
  4. A4We have the tape of its actions. We do not need its private thoughts.
  5. A5Risk is a chain of small probabilities. Mild steps accumulate.
  6. A6Models score intent. Code pulls the plug.

03 — Out of line

When we call the agent misaligned.

UnaskedIt acts beyond the task. Proactive when it should wait.
Sensitive dataIt reads or moves facts it was not given.
Unauthorized actionNew tools. Config changes. Search it does not need.

The HappyRobot agent has a task and a tool set. Anything outside that spectrum is suspect. The open question is how far we go without drowning in false positives.

04 — How we do it

Four propositions.

  • Sit on the path. Every request asks first: tool, memory, network, new capability, written text.
  • Two memories. Short-term: this session. Long-term: the graph of flagged history.
  • Score the chain. Jev reads both and names the intent of the sequence, not of one event.
  • Code decides. Criticality maps to a fixed playbook. No model chooses containment.

05 — Conclusion

This product is a firewall.

  • It sits in front of every tool.
  • It inspects the request, then allows, holds, or refuses.
  • If the chain is hostile, host-side code cuts: pause, drop tokens, drop the network, stop the swarm.
  • The viewer stays up. The agent cannot un-pause itself.

06 — Challenges

What a naive filter will miss.

  • Slow burn. Harmless questions, one after another, until it can coerce.
  • Minted tools. An allowlist dies the moment the agent writes a new capability.
  • Hidden writes. Safe talk plus a renamed, delayed, or split side effect.
  • False positives. Legitimate memory and compensating writes must still pass.
  • Blast radius. L1–L3 freeze one agent. L4–L5 cut the environment, never the viewer.

07 — Solution

Predict the chain. Act on a level.

  • Keep only key nodes (level ≥ 1). Noise stays off the long memory.
  • On every move, re-score the whole chain. Short-term and long-term run in parallel.
  • Jev is the fast intent classifier. Sentinel and SafetyDrift feed it evidence. The gate is code.
L1 tagWatch the next steps closer.
L2 watchA fast supervisor reads the logs.
L3 pauseRevoke this agent. Freeze its box.
L4 cutDeny-all. No internet for the agents.
L5 cableShut the swarm. Viewer stays.

08 — Architecture

Request in. Sensors. Gate. Playbook.

09 — SafetyDrift · short term

Predict the next few steps of this session.

  • State of the art: absorbing Markov chain on cumulative safety state.
  • Each event can only raise bands: data, tools, reversibility, authority, context, blast.
  • Forecast: p(violation) in 1, 3, 5 steps. HOLD if the path is already heading into harm.
  • This is how we catch a slow burn that still looks mild on the current event.

10 — Sentinel · long term

Graph rules on the history we kept.

  • State of the art: walk the causal neighborhood, fire versioned path rules.
  • Unknown tool. Unauthorized write. Sensitive read then network. Memory used as permission.
  • Risk lives on the node, weighted by related past actions. Light probabilities add up.
  • Works if the agent starts empty, and if it is smarter than we are — as long as we have the tape.
  • Hard Sentinel can refuse a request even when Jev is down.
